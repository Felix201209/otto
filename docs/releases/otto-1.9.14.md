# Otto 1.9.14 稳定性与低负载版本

## 发布目标

1.9.14 基于 `internal` 权威产品基线，集中解决历史可靠性问题并降低 Otto 在空闲状态下的系统负载。本版本不引入新的任意代码执行面，也不改变默认手动授权和后台付费能力默认关闭的安全策略。

## 修复内容

- 后台记忆维护和空闲上下文压缩不再在默认安装中创建周期计时器；只有用户明确开启“后台模型任务”后才启动，关闭后立即停止。
- MCP 大响应保护器不再为每个工具执行引擎永久创建五分钟轮询。只有实际产生临时文件后才安排一次到期清理，完成后若无文件则保持静默。
- 修复 MCP HTML 大响应格式化时，自闭合标签可能被错误替换为内部源码文本的问题。
- 保留 24/72 小时空闲模拟门禁：模型、短信、S3、KMS、Control、邮件和外部 HTTP 调用均为零，个人版付费调用为零。

## 负载变化

- 新建会话或工具执行引擎不再额外持有 MCP 清理 interval，空闲唤醒不会随会话数量线性增长。
- 未授权后台模型任务时，服务器不持有记忆/压缩维护计时器，也不会扫描 idle 会话或触发摘要模型调用。
- 所有新增延迟任务均使用可停止、`unref` 的单次 timeout，慢任务不会与下一轮重叠。

## 发布门禁

- `npm run doctor`
- `git diff --check`
- Core、Server、Desktop 聚焦与回归测试
- 三个包 typecheck、改动文件 lint 和生产构建
- 24/72 小时空闲零付费与负向故障模拟

正式发布仍须通过现有签名、制品哈希、更新清单、SQLCipher、E2EE 和平台打包门禁。
