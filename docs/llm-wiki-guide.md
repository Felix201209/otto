# Otto 知识库

Otto 会在正常使用过程中自动整理知识。用户不需要理解 LLM Wiki、RAG、向量库或目录结构，也不需要先初始化知识库。

## 直接使用

像平常一样与 Otto 工作即可：

- 让 Otto 阅读项目、文档或网页；
- 一起完成排查、设计、开发或研究；
- 告诉 Otto 你的长期偏好和团队约定；
- 在之后的会话中直接询问以前形成的结论。

Otto 会从经过验证的工作结果中提取有复用价值的内容，自动分类、脱敏、去重并保存。低置信度猜测、普通闲聊、临时状态和疑似密钥不会进入知识库。

## 用户可以说什么

不需要记命令，直接用自然语言：

- “我们之前为什么选择这个方案？”
- “以后都按这个命名规则。”
- “记住我不希望后台产生模型费用。”
- “整理一下这次故障的原因和解决办法。”
- “把这批资料中的共同结论整理出来。”
- “这个结论已经过期，按现在的实现更新。”

明确说“记住”时，Otto 会把它作为高置信度知识处理；没有明确说时，Otto 也会在任务完成后自动判断是否值得沉淀。

## 自动整理内容

知识通常归入以下类型：

- 用户偏好；
- 已确认的产品或工程决策；
- 验证通过的故障原因和解决方案；
- 可重复使用的研究结论；
- 项目约定和工作流程。

重复出现的知识会被合并和加强，而不是不断生成副本。长期未使用或被新事实替代的内容会降低可信度；当前代码和最新验证结果始终优先。

## 隐私与费用

- 个人知识库存放在本地用户数据目录中。
- 自动沉淀会过滤 API Key、Token、密码、Cookie 和私钥等敏感内容。
- 知识整理不意味着允许后台付费分析；后台模型任务仍然默认关闭，只有用户明确开启后才可以运行。
- 企业知识同步必须继续遵守组织权限、审计和数据治理规则。

## 高级维护

普通用户不需要管理存储文件。排查问题时，开发者可通过 `knowledge_base` 工具和知识状态接口检查条目、分类、去重及捕获统计；这些属于诊断能力，不是日常使用前提。

项目内若存在 `.llm-wiki/`，Otto 也可以把它作为可浏览的结构化项目 Wiki 使用。该目录是可选的展示层，不是个人知识库自动工作的前置条件。
