# 企业自助认证与自动开通

## 目标

把“平台管理员手工创建企业和 CEO”改为可审计的自助流程：

1. 个人账号提交企业主体资料。
2. Otto 自动完成格式、校验位、材料完整性和重复主体检查。
3. 低风险申请在接入权威工商数据服务后可自动核验；未接入前必须进入人工复核。
4. 平台审核通过后，在同一事务中把个人空间升级为企业空间，并把申请人设为 CEO。
5. 客户继续使用原账号和密码，不创建默认密码，不通过聊天或日志传递秘密。

## 信任边界

- 统一社会信用代码校验只能证明“代码格式可能有效”，不能证明申请人有权代表该企业。
- 营业执照 OCR 只能减少录入，不能单独作为自动批准依据。
- 普通企业管理员不能审核企业主体申请，也不能认证自己的企业。
- 共享托管环境由 Otto 平台身份审核；私有化部署若需要“Otto 官方认证”标识，必须由 Otto Control 签发可验证的认证凭证，客户服务器本地审核不能替代该凭证。
- License 只能由 Control 的签名链签发。企业审核接口不得在客户服务器本地生成或伪造 License。

## 状态机

```text
manual_review -> approved
              -> rejected
              -> cancelled (仅申请人、仅审核前)
```

本地自动检查失败直接拒绝提交，并返回可修正的输入错误。自动检查通过只进入
`manual_review`，不会在没有权威工商核验适配器时自动批准。

## 数据处理

- 数据库保存申请状态、统一社会信用代码、材料摘要和审计字段。
- 法定代表人姓名、对象存储键和材料引用使用字段级加密。
- 营业执照和授权书进入加密对象存储，数据库不保存文件正文。
- 支持 PDF、PNG、JPEG；单个文件最大 8 MB。
- 服务端重新计算 SHA-256，不信任客户端提交的摘要。
- 材料引用绑定申请账号、来源组织和材料用途，其他账号不能复用。
- HTTP 错误、审计日志和遥测不得包含材料正文、对象存储键、手机号或法定代表人姓名。

## 审核通过后的原子变更

批准操作在一个数据库写事务中完成：

1. 锁定申请并复查状态。
2. 确认申请人仍是个人账号，且个人空间没有其他活动账号。
3. 更新组织名称和规范化标识。
4. 创建默认管理部门和 CEO 员工记录。
5. 将现有账号升级为企业账号并授予 CEO/企业管理员权限。
6. 写入审核决定、目标组织和审计时间。

任何一步失败都回滚，不留下“企业已创建但 CEO 未创建”的半成品。

## 后续自动核验适配器

权威工商数据服务应作为可替换适配器接入，输出来源、查询时间、匹配字段、风险项和
供应商响应摘要。自动批准至少要求：

- 企业名称、统一社会信用代码、登记状态一致。
- 法定代表人或经办授权链可验证。
- 手机号或企业邮箱完成独立验证。
- 申请没有命中重复主体、异常设备、频繁提交和风险名单。
- 原始供应商响应按合规期限保留，且不进入普通业务日志。

适配器不可用、超时、限流或结果冲突时必须回退到人工复核，不能 fail-open。

## 验收

- 个人账号能上传材料并提交一次申请。
- 企业账号不能重复申请创建另一企业。
- 申请人只能查看和取消自己的待审核申请。
- 企业管理员无法读取或审批申请。
- 平台身份可以查看材料、驳回或批准；重复批准不产生重复企业或员工。
- 伪造材料引用、摘要不匹配、错误校验位、越权读取均被拒绝。
- 事务故障后账号、组织、员工和申请状态保持一致。
- 审核通过后原账号会话仍有效，重新读取身份即可进入企业工作区。
