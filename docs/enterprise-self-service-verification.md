# 企业自助开通

## 目标

企业创建采用即时自助开通流程，不再要求平台管理员预先创建企业，也不设置人工审核环节。

1. 已登录用户只填写企业名称。
2. 系统从当前登录会话读取账号 ID、姓名和已验证手机号，用户无需重复填写。
3. 服务端校验企业名称、登录状态和手机号验证状态。
4. 校验通过后，系统在同一事务中创建企业、升级当前个人空间，并授予当前账号 CEO/企业管理员权限。
5. 用户继续使用原账号和登录凭证，重新读取身份后即可进入企业工作区。

## 产品边界

- 该流程是 Otto 平台的企业功能自助开通，不是权威工商主体认证。
- Otto 不要求也不收集统一社会信用代码、法定代表人姓名、营业执照、授权书或申请人身份类型。
- 企业成功开通不代表 Otto 已核验企业登记状态、法定代表人或申请人的企业代表权限。
- 产品界面和对外文案不得使用“工商认证”“官方主体认证”等可能造成误解的表述。
- License 仍由 Otto Control 的签名链签发，自助创建企业不得在客户服务器本地生成或伪造 License。

## 即时开通流程

```text
填写企业名称
  -> 校验登录会话与已验证手机号
  -> 原子创建企业并升级当前账号
  -> 返回已开通企业身份
```

新申请不进入 `manual_review`。后台仅保留操作审计，以及对历史
`manual_review` 数据的兼容读取和迁移能力，不再承担新企业申请的审批职责。

## 数据处理

- 用户主动提交的数据只有企业名称。
- 账号 ID、姓名和已验证手机号来自可信登录会话，不接受客户端另行指定或覆盖。
- 数据库保存企业、账号、成员关系、角色和必要的开通审计记录。
- 审计记录包含操作者账号、目标企业、操作结果和时间，不记录密码、会话令牌或其他秘密。
- 企业开通接口必须校验当前会话，防止为其他账号创建企业或授予权限。
- 不建立营业执照、授权书等证明材料的上传、存储或下载链路。

## 原子变更

企业开通在一个数据库写事务中完成：

1. 校验当前会话有效，手机号已经验证。
2. 确认当前账号仍属于可升级的个人空间，且没有重复开通企业。
3. 校验企业名称并生成稳定、唯一的组织标识。
4. 创建企业组织和默认管理部门。
5. 创建或更新当前用户的企业成员记录。
6. 将当前账号升级为企业账号，并授予 CEO/企业管理员权限。
7. 写入开通结果和审计时间。

任何一步失败都必须回滚，不得留下“企业已创建但管理员未建立”或“账号已升级但企业不存在”的半成品。

## 历史兼容

- 已存在的 `manual_review` 记录继续可查询，避免升级后丢失历史状态。
- 历史记录可以按迁移策略归档、取消或转换，但不得阻塞新的即时开通流程。
- 旧审核接口不得成为新申请的必经步骤，也不得重新要求用户提交已取消收集的主体资料。

## 验收

- 已登录且手机号已验证的个人账号只填写企业名称即可开通企业。
- 未登录、手机号未验证、企业名称无效或账号已属于企业时，服务端明确拒绝开通。
- 客户端不能伪造账号 ID、姓名、手机号或为其他账号授予 CEO/企业管理员权限。
- 重复提交不会创建重复企业、成员或角色记录。
- 并发提交只能有一次成功，其余请求得到可理解的幂等或冲突结果。
- 事务故障后账号、组织、成员和权限状态保持一致。
- 开通成功后原账号会话仍有效，重新读取身份即可进入企业工作区。
- 后台可以审计开通事件并查看历史 `manual_review` 记录，但新申请无需人工批准。
- 系统不收集统一社会信用代码、法定代表人、营业执照、授权书或申请人身份。
