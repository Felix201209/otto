# 园区服务上线待办

> 状态：产品规则已确认，以下两项尚未实现。此文件随下一次代码同步后供 Felix 和所有开发成员共同查看。

## P0：多人待办的抢单与退回

- 维修工作人员、园区客服人员都允许配置多名。
- 同一申请会进入符合职责标签的所有人员待办池。
- 第一名点击“接单并处理”的人员获得工单，服务器必须用原子更新保证只有一人抢单成功；其他人立即看到“已由某某接单”，不能继续处理。
- 工作人员选择“暂时没空”时，工单退回公共待办池，可由其他符合条件的人员接单。
- 数据库需要记录实际处理人、接单时间、退回时间和退回原因；接口冲突应返回明确状态，客户端同步刷新。
- 必须覆盖双设备同时接单、接单后退回、退回后重新接单、已完成工单不可重抢的自动化测试。

## P0：通知升级顺序

- 新申请、办理回复和办理结果：Otto 站内提醒与飞书立即发送。
- Otto 提醒发出 5 分钟后仍没有已读回执，才发送短信；已读则取消短信。
- 延时任务需要在服务器重启后继续有效，不能只依赖内存计时器。
- 每个渠道保留发送状态、失败原因和重试次数，管理员可以排查；普通用户不能看到手机号、飞书 open_id 或通知日志。
- 短信与飞书失败不能阻断工单创建，失败任务进入可重试队列。
- 必须覆盖 5 分钟内已读不发短信、超时未读发送短信、重复任务不重复发送、服务器重启后继续执行的自动化测试。

## 上线验收

- 上述两项完成前，当前服务器仍会把短信和飞书同时即时发送，且多人接单尚未做唯一锁定。
- 完成后使用两台 Otto 和两个工作人员账号做一次端到端验收，再打正式安装包。
