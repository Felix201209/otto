# Otto 数据治理与合规实施基线

> 本文是产品与工程控制基线，不替代律师针对客户、行业和部署地出具的法律意见。

## 责任边界

- 私有化部署客户决定账号、企业协作、园区业务和模型供应商的处理目的与方式，通常承担客户侧个人信息处理者责任。
- Otto 运营方仅在 License 校验、客户明确启用的健康遥测和支持诊断范围内处理最小必要数据。
- 聊天原文、附件、会议内容和个人记忆默认不进入运营遥测。
- 正式交付前必须配置 `OTTO_DATA_CONTROLLER_NAME` 和 `OTTO_PRIVACY_CONTACT`，由客户法务确认当前版本的完整用户协议、隐私规则和员工告知文本后，再把 `OTTO_LEGAL_DOCUMENTS_APPROVED` 设为 `true`。未确认时服务健康状态保持未就绪。

## 数据位置与跨境

- 账号、组织、私聊、园区工单和业务统计存储在用户选择的企业服务器。
- 个人记忆、工作日志和自动 Skill 保留本机副本；跨设备快照存储在该账号连接的企业服务器并使用 AES-256-GCM 加密。
- 模型请求会发送给客户自行配置的模型供应商，其地域和留存规则应单独审查。
- 默认配置为 `CN + customer_server + cross-border=false`。不得把“关闭跨境标记”当作技术阻断；启用境外模型或境外遥测前仍须完成数据流梳理、影响评估、单独同意及适用的数据出境程序。

## 静态与传输保护

| 数据 | 静态保护 | 传输 |
| --- | --- | --- |
| 密码、会话令牌、短信验证码 | 只保存强哈希 | HTTPS/TLS，令牌放在 Authorization 请求头 |
| 个人记忆、工作日志、自动 Skill | 服务器快照使用 AES-256-GCM；桌面同步镜像使用 Electron 系统安全存储；活动文件依赖系统磁盘加密 | HTTPS/TLS |
| 私聊正文与附件对象 | 客户端执行端到端加密，企业服务器与对象存储只保存密文、设备信封和必要路由元数据 | HTTPS/TLS 叠加设备级加密与签名；当前不是 Signal Double Ratchet |
| License 租约令牌与遥测令牌 | 使用 AES-256-GCM 字段加密；旧授权中的明文令牌启动时迁移 | 租约与遥测仅允许 HTTPS，遥测另有请求签名与防重放 |
| 数据库业务字段 | 桌面端 SQLite 使用 SQLCipher；企业集群 PostgreSQL 依赖加密卷/KMS，并可对必要字段使用信封加密 | 公网仅允许 HTTPS/TLS |
| 备份 | 完整归档 AES-256-GCM | 异地副本走客户控制的安全通道 |
| 健康遥测 | 内容字段拒收、本地队列 | 仅 HTTPS；Bearer 令牌 + HMAC-SHA256 请求签名 + 5 分钟时间窗 + nonce 防重放 |

桌面端与离线部署使用 SQLite/SQLCipher 保留离线能力；企业集群以 PostgreSQL 作为权威数据源，禁止通过 NFS/SMB 共享 SQLite 文件供多实例并发写入。PostgreSQL 不使用 SQLCipher，应通过 TLS、加密卷/KMS、最小权限和必要字段级信封加密保护。无论后端类型，组织 ID、状态、时间和统计等检索字段仍可能是结构化数据，部署方必须按其敏感级别配置基础设施保护。
部署方只有在完成上述磁盘保护后才能设置 `OTTO_STORAGE_VOLUME_ENCRYPTED=true`；否则“隐私与数据”页会返回未就绪告警。

### 传输协议边界

- 一键部署的 Caddy 只接受 TLS 1.2 和 TLS 1.3，并设置 HSTS、`nosniff`、禁止 iframe 和严格 Referrer Policy。
- Caddy 只把请求转发到 `127.0.0.1:7778`，Node 企业服务不得直接暴露公网端口。
- 普通 API 请求体限制为 1 MB；私聊附件上传路由单独限制为 32 MB，用于容纳“单文件 10 MB、每条总计 20 MB”的 Base64 传输开销。
- 企业私聊当前采用 HTTPS 轮询/请求，不是 WebSocket，也不是端到端加密。企业服务端为实现权限校验、A2A 和审计可解密正文，因此客户服务器管理员属于信任边界。
- 模型请求只允许发送到客户配置的 HTTPS 供应商；是否跨境、是否留存及供应商侧加密由客户选择的供应商协议决定。

### 密钥管理边界

- 业务字段、附件对象、账号同步和备份使用不同密钥，备份归档会保存恢复所需的业务密钥，并由独立的备份密钥再次加密。
- 可通过 `OTTO_FIELD_ENCRYPTION_KEY_FILE`、`OTTO_ATTACHMENT_ENCRYPTION_KEY_FILE` 和 `OTTO_ACCOUNT_SYNC_ENCRYPTION_KEY_FILE` 把 32 字节原始密钥挂载到数据目录之外；客户托管密钥恢复时必须与备份内密钥一致，程序不会覆盖外部密钥。
- `OTTO_BACKUP_ENCRYPTION_KEY_FILE` 使用 32 字节 Base64 或 64 位十六进制密钥，应由客户与交付方按合同离线托管。丢失备份密钥或业务密钥都将导致对应数据不可恢复。
- 密钥文件必须是普通文件，不允许符号链接，并只向 Otto 服务账号授予读取权限。生产环境需要制定生成、备份、轮换、吊销和双人恢复流程。

## 权限与越权控制

- HTTP 路由先做身份策略判断，再做企业、部门、岗位和产业园作用域判断。
- License 和模块开关在服务端执行层 fail-closed，UI 隐藏不构成授权。
- 数据导出和注销仅限当前登录账号本人；注销必须再次验证密码和精确确认文本。
- 企业最后一名有效管理员不能直接注销，必须先完成权限移交。
- 私聊附件只允许消息双方下载；产业园业务数据只允许所属企业与授权园区工作人员访问。

## 导出、注销与恢复

- 用户可以在“设置 > 隐私与数据”查看处理目录、协议版本、License 和遥测状态，并导出本人 JSON 数据。
- 注销会删除会话、账号标签、个人记忆快照、工作日志、用量明细、在线状态、本人私聊与附件，并清理当前电脑上的托管记忆、日志和自动 Skill。
- 账号、员工、园区工单联系人、知识贡献者、积分说明和审计详情按用途匿名化。
- 园区年度次数、时间、状态、数量和金额统计，以及财务和安全审计所需记录可以最小化保留，但不得继续用于营销或用户画像。
- 删除台账独立于业务数据库并使用 AES-256-GCM；加密备份包含该台账。恢复旧备份时保留服务器上更新的删除台账，启动后再次执行删除，避免已注销数据复活。

## 留存与运营

- 健康遥测默认保留 90 天，可通过 `OTTO_TELEMETRY_RETENTION_DAYS` 缩短；到期由执行层清理。
- 安全审计日志至少保留 180 天；超过法定或合同期限后的上限仍需客户制定并验证清理策略。
- 加密备份默认保留 30 天且至少保留 3 份；生产环境应配置异地副本、容量告警和定期恢复演练。
- 收到查阅、更正、删除或投诉请求后，应核验身份、记录处理结果，并在适用法律期限内响应。

## 上线前必做

1. 客户法务确认协议、隐私规则、处理者名称、联系方式、合法性基础和行业额外义务。
2. 完成实际数据流、模型供应商、短信、飞书、备份和遥测接收方清单。
3. 对敏感个人信息、自动化决策、园区大规模处理和跨境场景完成个人信息保护影响评估。
4. 验证 HTTPS、License、模块权限、附件鉴权、导出、注销、备份恢复和删除台账回放。
5. 配置安全事件响应、漏洞处置、日志审计、密钥轮换、灾难恢复和账号离职流程。
