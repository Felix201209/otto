# Otto 数据治理与合规实施基线

> 本文是产品与工程控制基线，不替代律师针对客户、行业和部署地出具的法律意见。

## 责任边界

- 私有化部署客户决定账号、企业协作、园区业务和模型供应商的处理目的与方式，通常承担客户侧个人信息处理者责任。
- Otto 运营方仅在 License 校验、客户明确启用的健康遥测和支持诊断范围内处理最小必要数据。
- 聊天原文、附件、会议内容和个人记忆默认不进入运营遥测。
- 正式交付前必须配置 `OTTO_DATA_CONTROLLER_NAME` 和 `OTTO_PRIVACY_CONTACT`，并由客户法务确认最终用户协议、隐私规则和员工告知文本。

## 数据位置与跨境

- 账号、组织、私聊、园区工单和业务统计存储在用户选择的企业服务器。
- 个人记忆、工作日志和自动 Skill 保留本机副本；跨设备快照存储在该账号连接的企业服务器并使用 AES-256-GCM 加密。
- 模型请求会发送给客户自行配置的模型供应商，其地域和留存规则应单独审查。
- 默认配置为 `CN + customer_server + cross-border=false`。不得把“关闭跨境标记”当作技术阻断；启用境外模型或境外遥测前仍须完成数据流梳理、影响评估、单独同意及适用的数据出境程序。

## 静态与传输保护

| 数据 | 静态保护 | 传输 |
| --- | --- | --- |
| 密码、会话令牌、短信验证码 | 只保存强哈希 | HTTPS/TLS，令牌放在 Authorization 请求头 |
| 个人记忆同步快照 | AES-256-GCM | HTTPS/TLS |
| 私聊附件对象 | AES-256-GCM | HTTPS/TLS，聊天双方鉴权 |
| 数据库业务字段 | 为检索、权限和统计保留结构化明文字段 | 公网仅允许 HTTPS/TLS |
| 备份 | 完整归档 AES-256-GCM | 异地副本走客户控制的安全通道 |
| 健康遥测 | 内容字段拒收、完整性签名、本地队列 | 仅 HTTPS，Bearer 令牌 |

SQLite 数据库当前不是整库透明加密。敏感对象和快照已单独加密；高安全客户应把数据目录放在 LUKS、BitLocker 或云盘加密卷中，并把密钥交由独立密钥系统托管。

## 权限与越权控制

- HTTP 路由先做身份策略判断，再做企业、部门、岗位和产业园作用域判断。
- License 和模块开关在服务端执行层 fail-closed，UI 隐藏不构成授权。
- 数据导出和注销仅限当前登录账号本人；注销必须再次验证密码和精确确认文本。
- 企业最后一名有效管理员不能直接注销，必须先完成权限移交。
- 私聊附件只允许消息双方下载；产业园业务数据只允许所属企业与授权园区工作人员访问。

## 导出、注销与恢复

- 用户可以在“设置 > 隐私与数据”查看处理目录、协议版本、License 和遥测状态，并导出本人 JSON 数据。
- 注销会删除会话、账号标签、个人记忆快照、工作日志、用量明细、在线状态、本人私聊与附件，并清理当前电脑上的托管记忆、日志和自动 Skill。
- 账号、员工、园区工单联系人、知识贡献者、积分说明和审计详情按用途匿名化。
- 园区年度次数、时间、状态、数量和金额统计，以及财务和安全审计所需记录可以最小化保留，但不得继续用于营销或用户画像。
- 删除台账独立于业务数据库并使用 AES-256-GCM；加密备份包含该台账。恢复旧备份时保留服务器上更新的删除台账，启动后再次执行删除，避免已注销数据复活。

## 留存与运营

- 健康遥测默认保留 90 天，可通过 `OTTO_TELEMETRY_RETENTION_DAYS` 缩短；到期由执行层清理。
- 安全审计日志至少保留 180 天；超过法定或合同期限后的上限仍需客户制定并验证清理策略。
- 加密备份默认保留 30 天且至少保留 3 份；生产环境应配置异地副本、容量告警和定期恢复演练。
- 收到查阅、更正、删除或投诉请求后，应核验身份、记录处理结果，并在适用法律期限内响应。

## 上线前必做

1. 客户法务确认协议、隐私规则、处理者名称、联系方式、合法性基础和行业额外义务。
2. 完成实际数据流、模型供应商、短信、飞书、备份和遥测接收方清单。
3. 对敏感个人信息、自动化决策、园区大规模处理和跨境场景完成个人信息保护影响评估。
4. 验证 HTTPS、License、模块权限、附件鉴权、导出、注销、备份恢复和删除台账回放。
5. 配置安全事件响应、漏洞处置、日志审计、密钥轮换、灾难恢复和账号离职流程。
