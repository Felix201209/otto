## 1. 适用事件

- 账号接管、越权访问、数据泄露或批量异常导出；
- 恶意代码、勒索、主机入侵、供应链或更新包篡改；
- 数据库损坏、误删除、备份失败、对象存储暴露；
- License、KMS/HSM、代码签名或 E2EE 设备密钥泄露；
- Otto Server、Control、Federation、模型或关键供应商大面积不可用；
- 跨租户串线、审计链损坏、联邦重放或伪造；
- 法律法规、主管部门或合同约定的其他安全事件。

## 2. 事件分级

| 级别 | 判断参考 | 响应目标 |
| --- | --- | --- |
| I 特别重大 | 大范围敏感数据、国家/公共利益重大影响、核心系统长时间不可用 | 立即升级最高管理层、法务和主管部门流程 |
| II 重大 | 多企业/园区受影响、核心密钥泄露、跨租户越权、较长中断 | 立即启动专项应急，优先隔离和止损 |
| III 较大 | 单企业重要数据、可控入侵、关键功能明显中断 | 迅速处置，限定时间恢复和通知 |
| IV 一般 | 小范围、无敏感数据、可快速恢复且无持续风险 | 常规事件流程，保留记录并整改 |

最终分级、报告时限和通知对象应由运营主体依据适用法规、行业规则和合同确认。

## 4. 通用响应流程

1. **发现与登记**：创建唯一事件编号，记录来源、时间、系统、症状和初步影响。
2. **分级与召集**：值班人员不得自行压低等级；按级别通知指挥和专业人员。
3. **隔离止损**：撤销账号/密钥、封禁部署、隔离主机、关闭模块或切断供应商，保留证据后操作。
4. **证据保全**：保存日志、审计链、内存/磁盘快照、配置、制品哈希、工单和时间线；计算哈希并记录交接。
5. **分析与清除**：确认入口、影响范围、横向移动、数据访问和持续机制，清除根因而非只恢复页面。
6. **恢复**：从可信版本和备份恢复，执行完整健康、安全、权限和数据核验，分阶段放量。
7. **通知与报告**：由法务和负责人确认监管、客户、个人和供应商通知的对象、内容与时限。
8. **复盘整改**：记录根因、时间线、损失、处置、控制缺陷和责任明确的整改项，验证关闭。

## 5. Otto 专项动作

| 场景 | 首要动作 | 关键核验 |
| --- | --- | --- |
| 跨企业越权 | 禁用相关路由/账号，保全审计和数据库快照 | tenant ID、资源 ACL、访问范围、缓存键 |
| Control/License 密钥泄露 | 紧急吊销 key ID，启用备用公钥和短租约 | 旧签名拒绝、历史 License 策略、审计链 |
| 发布物篡改 | 下架制品和 manifest，阻断更新，吊销发布身份 | SHA-256、代码签名、来源提交、受影响设备 |
| E2EE 设备丢失 | 撤销设备，停止分发后续密钥，提醒联系人核验 | 设备证书、透明日志、恢复流程 |
| 数据库/备份事件 | 停止破坏性写入，在隔离环境恢复 | schema、逻辑哈希、注销台账、附件 ACL |
| Federation 滥用 | block deployment/key，暂停投递和 grant | 签名、序列、重放、积压和回执 |
| 模型供应商泄露 | 停用供应商凭据和路由，确认发送数据范围 | 提示词范围、地域、留存、供应商通知 |

## 6. 通知模板字段

事件编号、发现时间、发生时间、涉及系统、影响对象和数量、数据类别、已采取措施、当前风险、用户建议、联系人、后续更新时间。禁止在通知中泄露密钥、攻击利用细节或其他客户数据。
