## 1. 目的和适用范围

本制度适用于 Otto 企业智能工作系统的规划、开发、测试、发布、部署、运营、客户支持、数据处理和退役活动。适用人员包括员工、外包、供应商和经授权的客户管理人员。

## 2. 安全组织与责任

| 角色 | 主要责任 | 不相容职责 |
| --- | --- | --- |
| 系统负责人 | 业务目标、资源和风险接受 | 不得单独批准自己的高风险操作 |
| 安全负责人 | 制度、风险、事件、漏洞和测评协调 | 不直接持有全部生产和密钥权限 |
| 数据保护负责人 | 数据目录、合法性、权利请求、供应商和跨境评审 | 不以运维便利扩大处理范围 |
| 开发负责人 | 安全设计、代码评审、测试和修复 | 不绕过发布门禁直接上线 |
| 运维负责人 | 配置、备份、监控、变更和恢复 | 不同时担任独立审计员 |
| 密钥管理员 A/B | KMS/HSM、轮换、吊销和恢复 | 双人分离，私钥不可导出 |
| 审计员 | 独立检查权限、日志、变更和证据 | 不改写被审计记录 |

正式副本必须填写姓名、替补人、联系方式和授权文件编号。

## 3. 人员与账号安全

- 入职前签署保密和安全责任文件，按岗位最小授权。
- 高权限人员背景、培训和授权按公司及客户制度执行。
- 调岗当天复核权限，离职立即禁用账号、会话、VPN、证书和密钥。
- 禁止共享管理员账号；高权限账号和云控制台启用 MFA。
- 至少每季度复核人员、服务账号、API 凭据和临时权限。

## 4. 开发和供应链安全

- 需求阶段完成数据、权限、滥用和威胁分析。
- 变更必须经过评审、测试和可追溯提交，不得直接修改生产文件。
- 发布执行单元、集成、安全、边界、异常和回归测试，并生成 SBOM、哈希和构建证据。
- 第三方依赖持续扫描；高危和严重漏洞未完成风险处置不得发布。
- Windows、macOS 和服务器部署物应执行正式签名，签名密钥进入 KMS/HSM 或隔离签名环境。

## 5. 配置、网络和终端安全

- 按 [端口清单](./04-port-and-communication-inventory.md) 最小开放，生产与测试隔离。
- 数据库、缓存、对象存储、指标和管理端不得公网裸露。
- 主机启用补丁、恶意代码防护、磁盘加密、时间同步和安全日志。
- 默认配置 fail-closed；不得用 UI 隐藏替代服务端权限校验。
- 配置变更通过工单审批并保留前后差异和回滚方案。

## 6. 数据和密钥安全

- 按数据目录实施分类分级、最小收集、用途限制、留存和删除。
- 口令只存强哈希；Token、业务敏感字段、附件和备份按设计加密。
- 公网传输使用 TLS；模型、飞书、短信和遥测接收方纳入供应商和数据流评审。
- 私钥禁止进入源码、普通构建机、日志、工单和聊天工具。
- 密钥生成、授权、轮换、吊销、备份和恢复执行双人控制并记录审计。

## 7. 备份、连续性和事件管理

- 按 [备份与恢复方案](./09-backup-and-recovery-plan.md) 执行备份、异地保存和恢复演练。
- 按 [应急预案](./10-incident-response-plan.md) 对泄露、入侵、勒索、不可用、密钥和供应链事件分级处置。
- 重大事件期间保全日志和证据，不在生产库直接“修复”审计记录。

## 8. 供应商和客户私有化责任

- 供应商准入前审查安全能力、地域、分包、事件通知、删除和退出条款。
- 私有化客户负责其云账号、网络、人员、数据目的和本地制度；Otto 交付方提供软件安全基线、部署说明、整改支持和合同约定的最小遥测。
- 责任边界必须进入合同和交付确认，不得用“私有化”笼统免除任何一方责任。

## 9. 检查、违规和复审

- 每季度检查资产、权限、漏洞、备份、审计和供应商；每年至少复审制度。
- 发现违规立即止损、保全证据、评估影响并按人事、合同和法律程序处理。
- 制度、系统边界或法规发生重大变化时提前复审，不等待年度周期。
