# Otto 交付测试矩阵

这份矩阵是 Otto 合入与发布前的统一验收入口。代码合入可以完成自动化项；标记为“实机”的项必须在对应系统或真实飞书环境执行，不能用单元测试替代。

## 平台矩阵

| 平台 | 最低验收入口 | 重点场景 | 证据 |
| --- | --- | --- | --- |
| macOS Apple Silicon | DMG 安装后的 Otto.app | 启动、菜单栏、模型切换、附件、系统通知、应用内更新 | 系统版本、安装包 SHA-256、截图、日志 |
| macOS Intel | DMG 安装后的 Otto.app | 启动、菜单栏、模型切换、附件、系统通知、应用内更新 | 系统版本、安装包 SHA-256、截图、日志 |
| Windows 10 x64 | NSIS 安装后的 Otto.exe | 启动、任务栏/托盘图标、右下角通知、附件、应用内更新 | 系统版本、安装包 SHA-256、截图、日志 |
| Windows 11 x64 | NSIS 安装后的 Otto.exe | 启动、任务栏/托盘图标、右下角通知、附件、应用内更新 | 系统版本、安装包 SHA-256、截图、日志 |
| 弱性能电脑 | 安装后的桌面客户端 | 低内存模式、长任务 checkpoint、上下文压缩与恢复 | CPU/内存、运行时长、恢复日志 |

## 结果记录

每次候选交付建立一份记录，禁止把未执行写成通过：

```text
版本或提交：
测试日期：
执行人：
平台与系统版本：
入口：
用例：
结果：PASS / FAIL / BLOCKED / NOT RUN
证据路径或链接：
失败关联 Issue：
```

只有所有 P0 自动化门禁通过、要求的实机项有真实记录、失败项都关联 Issue 后，才能给出 go/no-go 结论。
