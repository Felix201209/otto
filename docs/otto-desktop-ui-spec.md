# Otto Desktop 渲染层 UI 规格（以示例图为唯一基准）

> 渲染层（Issue 5/6/7）必须 1:1 还原下述布局。主题 = **浅色**，强调色 = **amber/橙（约 `#E8893A`，hover/深一档 `#E07B2E`，浅底 `#FDEFE3`）**，文字主色近黑 `#1d1d1f`、次级灰 `#8a8a8e`，分隔线 `#ececec`，圆角 ~12px，字体 PingFang SC / 系统无衬线 + 代码用等宽。整体干净留白、不堆砌。

## 窗口
- 圆角窗口；左上角 mac 红黄绿交通灯（在侧栏顶部）。
- 右上角：圆形头像「F」（amber 圆底白字）= 当前用户。

## 左侧栏（约 260px，底色近白 `#f7f7f8`）
1. 顶部品牌：小写 **`otto`** 字标（amber→橙渐变）+ 紧跟一个小 `✦` 火花；同行右侧一个「新建/compose」小图标按钮。
2. **`+ 新建对话`** 按钮：整宽、白底、细边框、圆角。
3. 分组标签 **`今天`**（小号灰字）。
4. 会话列表项（**选中项**：浅 amber/cream 底 `#FDEFE3` + 左侧 amber 竖条）：
   - 标题（如「优化用户登录流程」）+ 右侧时间（11:24，小灰字）。
   - 第二行：预览文本（单行省略，如「我来帮你优化登录流程的代码…」）。
   - 来源徽章：**`Feishu`**（蓝/青系小标签 + 小蓝色飞书花瓣图标）或 **`Local`**（绿系小标签 + 灰色方块/勾选图标）。
   - 列表示例：今天=优化用户登录流程(Feishu,选中) / 修复数据导出问题(Local) / 实现定时任务(Feishu)；昨天=接口性能优化建议(Local) / 增加登录设备管理(Feishu) / 前端页面加载慢(Local)。
5. 分组标签 **`昨天`** + 同样的列表项。
6. 底部：**`≡ 查看全部对话 ›`** 按钮。

## 主聊天区（白底）
1. **用户消息**（右对齐）：peach/cream 圆角气泡（如「帮我优化一下登录流程的代码，减少重复验证逻辑」）+ 右下时间 `11:24` + amber 双勾 `✓✓` 已读回执。
2. **Otto 回复**（左对齐）：
   - Otto 头像（圆形机器人吉祥物，先用简洁 SVG 占位，Felix 后续替换）+ 名称 **`Otto`** + 时间。
   - 正文段落（如「我来帮你优化登录流程的代码…提取为公共方法。」）。
   - 折叠卡片标题：**`调用了 1 个工具`** + 折叠箭头。
   - **工具卡 1 — 编辑文件**：文件图标 + `编辑文件` + 路径 `src/services/auth/login.ts` + 右侧绿色 `✓ 已完成` + 折叠箭头。展开为 **diff 视图**：
     - diff 头：`@@ -45,15 +45,10 @@ async function login(credentials: LoginRequest) {`
     - 行号列 + 删除行（红底，如 `if (!credentials.email) { throw new Error('邮箱不能为空') }` 等）+ 新增行（绿底，如 `validateLoginInput(credentials)`）+ 上下文行（无底色）。等宽字体、红/绿背景。
   - **工具卡 2 — 终端运行**：终端图标 + `终端运行` + `npm run lint` + 绿色 `✓ 已完成`（默认折叠）。
   - 收尾正文：「登录流程已优化完成！…通过单元测试确保功能正常。」（行内代码 `validateLoginInput` 用等宽+浅灰底）。
   - 动作行：复制 / 重新生成(↻) / 赞(👍) / 踩(👎) 四个灰色图标。

## 底部输入区
- 大号圆角输入框，占位符 **`给 Otto 发送消息...`**。
- 左下：**模型选择器 pill**（`claude-opus-4 ▾`）+ 回形针附件图标。
- 右下：**amber 圆形发送按钮**（向上箭头/→）。

## 交互态（按设计质感补全）
- 会话项 hover：浅灰底；选中：amber cream 底 + 左竖条。
- 按钮/图标 hover/active 状态都要有，不能是裸默认。
- 流式回复时 Otto 正文有打字/光标指示；工具卡有「运行中→已完成」状态切换。
- 来源徽章颜色语义化：Feishu=蓝青、Local=绿。

## 数据来源（与架构对齐）
- 会话来源 `source: feishu | local`，徽章据此渲染；飞书会话实时经 WS 同步（Issue 6，双向）。
- 全部会话/消息/工具调用/流式增量 经 preload 的 server WS 通道获取（Issue 2 协议）。
