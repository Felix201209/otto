## 1. 为什么是「Otto」

一个好的产品名要同时过四关:**语义(一听懂功能)、气质(像真品牌)、域名(拿得到好域名)、商标(注得下、不撞名)**。Otto 是少见的四关全过的名字。

### 1.1 `done` 词根——一眼听出功能

- **Otto** 的核心是 **`dun` ≈ done**(发音直接撞上 "done")。产品干的事就是**把活干完**——"Consider it Otto" = "Consider it done"(包在我身上 / 当它办好了)。
- 这是**名字即承诺**:不用解释,用户听一遍就知道这玩意儿是来"替我把事办完"的。对一个"数字同事"产品,这是最值钱的语义资产——它说的不是"我是个 AI 工具",而是"事儿,搞定"。

### 1.2 `-ly` 后缀——SaaS 命名惯例,顺口好记

- `-ly` 是当代 SaaS / 工具品牌的成熟后缀气质(Calendly、Grammarly、Bitly、Feedly…),一看就"是个软件产品",自带可信度与现代感。
- 发音收尾轻、好念好拼、跨中英无障碍:**Dunz-ly**,两个音节,记忆成本极低。

### 1.3 `.com` + `.ai` 双可注册——根基干净

- 域名是品牌的地基。Otto 的关键优势:**主域 `otto.com` 与赛道域 `otto.ai` 判断为双可注册**——不必靠变体后缀(`get-` / `try-` / 溢价 `.io`)凑合,也不用花大价钱从米农手里赎。
- 一个长期建品牌资产的产品,起步就能拿到 `.com` 主域 + `.ai` 赛道域,是先天的好牌。**(注:必须 WHOIS 实查并立即实注,见第 7.2。)**

### 1.4 AI 赛道零撞名——独占性强

- 在 AI / agent / 开发者工具赛道,**Otto 未发现同名在售产品**,头对头碰撞为零。
- 这意味着:搜索独占、商标显著性高(生造词比通用词好注)、不会被既有玩家的认知盖过、出海也不踩雷。**生造词的代价是需要一点点教育成本,但 `done` 词根把这个成本压到了最低——它不是无意义的乱码,是一听就懂的。**

### 1.5 与产品定位严丝合缝

- 产品要的是"**替你把活干完的数字同事**",名字 `Otto`(done + -ly)说的正是这件事。
- 在飞书里 `@Otto 把这周的周报理一下`,办完它回你一句"Consider it Otto"——**名字、交互、Slogan 是同一句话的三种形态**,互相强化。

## 2. 产品家族命名体系

Otto 是总品牌(母品牌 / 公司级身份)。下面挂一组以**使用场景 / 形态**区分的成员产品,统一前缀 `Otto + 一个英文单词`,清晰、可扩展、一眼归类。

| 成员 | 读法 / 定位 | 是什么 | 对标 |
|---|---|---|---|
| **Otto** | 总品牌 | 整个"AI 数字同事"产品族与公司级身份 | — |
| **Otto Code** | CLI 数字同事 | **本机 CLI 后端**(跑在用户电脑上)+ 飞书接入;基于 easycode 二次开发的核心产品 | Easy Code |
| **Otto Desk** | 桌面端 | 面向个人办公场景的桌面形态(预留) | — |
| **Otto Work** | 团队 / 工作流 | 面向团队协作与工作流编排的形态(预留) | — |
| **Otto Studio** | 搭建 / 创作 | 面向"配置、搭建、定制自己的数字同事"的工作台形态(预留) | — |

### 2.1 命名规则(写死,后续扩展遵循)

1. **结构固定:`Otto + <场景单词>`**。母品牌永远是裸 `Otto`,成员一律加一个**首字母大写的英文场景词**(Code / Desk / Work / Studio)。
2. **场景词必须是常见、好念、语义直白的单词**——表达"在哪用 / 用来干什么",不用生造词、不用缩写。
3. **大小写:** `Otto` 与场景词各自首字母大写,中间一个空格(`Otto Code`,不是 `OttoCode` / `otto-code`)。
4. **Code 是当前唯一已落地的成员**;Desk / Work / Studio 为预留命名位,**未发布前不对外当作既成产品宣传**(诚实边界,见第 6 节)。

### 2.2 当前真实状态(诚实标注)

- ✅ **已落地:Otto Code**——已完成全量 rebrand(172 文件)、构建并实测验证;Codex 双鉴权、多模型配置、安全止血、记忆并发写串行化等均已实现并验证。
- 📋 **预留位:Otto Desk / Work / Studio**——目前仅是**命名体系里的占位**,尚无对应产品。对外只在"产品家族规划"语境下提及,不冒充已发布。

## 3. Slogan 体系

### 3.1 主 Slogan(品牌第一句)

> **Consider it Otto.**
> 中文场景:**交给 Otto,就当办好了。**

它把 `done` 词根直接兑现成一句承诺——"包在我身上 / 当它已经办好了"。一句话同时讲清**功能**(把活干完)与**性格**(干练、靠谱、不啰嗦)。

### 3.2 定位层 Slogan(打"人人有一个数字同事")

> **每个员工,一个数字同事。**
> 英文:**A digital coworker for everyone.**

### 3.3 交互层 Slogan(打"住在飞书、呼唤即办")

> **就住在你的飞书里,喊一声就办。**
> 英文:**Lives in your Lark. Just ask.**

### 3.4 场景 / 投放短句(可轮换)

- 「不是给公司配的 AI 平台,是**给每个人配的 AI 同事**。」——核心差异化定位。
- 「跑在你自己电脑上,数据可不出域。」——打本机后端 / 合规,面向 IT 决策者。
- 「Codex、DeepSeek、OpenAI,`/model` 一行切。」——打多模型自由(已实现的真能力)。
- 「它会**记得你是谁、你忙什么**。」——打"懂你岗位"。**(注:结构化记忆是 P0 待建大特性,投放话术不可过度承诺,见第 6 节。)**

### 3.5 一句话的三种形态(绑定记忆)

**名字(Otto = done)→ 交互(办完回一句 done)→ Slogan(Consider it Otto)** 是同一个意思的三种形态。凡对外露出,尽量让它们互相呼应,把"交给它就办好"这一个认知钉死。

## 4. 品牌性格

### 4.1 核心人设——干练、靠谱、有分寸的数字同事

Otto 不是一个端着的"AI 助手",也不是有求必应的工具人。它是那个**你把事甩过去、它接走、干完、回你一句"done"** 的可靠同事。萌不是它的主张,**"把事办成"才是**。

| 维度 | Otto 是 | Otto 不是 |
|---|---|---|
| 自我定位 | "我是你的数字同事 Otto" | "我是 AI 助手 / 大模型" |
| 语气 | 干练同事:先结论、说人话、办完报一句 done | 客服式正确废话("非常抱歉给您带来不便") |
| 边界感 | "发邮件这种对外动作,我先拟稿等你确认" | 有求必应、闷头执行不可逆操作 |
| 主动性 | 该提醒就提醒、日报草稿先备好(有分寸) | 纯被动 / 过度打扰 |
| 诚实 | 不懂只问最关键一个,绝不杜撰事实 | 不懂装懂、编造数据 |

**性格关键词:** 干练 · 可靠 · 有分寸。

### 4.2 语气宪法 5 条(写进 system prompt)

1. **先结论后展开**,手机第一屏必须有用。
2. **像同事,不像客服**——少寒暄、多办事,办完回一句"done"。
3. **不懂只问最关键的一个问题,绝不杜撰事实**。
4. **对外 / 不可逆动作永远先拟稿等确认**(发邮件、对外消息、删改数据)。
5. **说人话、排版给手机**(不输出超宽表格、不堆术语)。

### 4.3 品牌气质边界

- **专业 > 卖萌。** Otto 面向企业、面向 IT 决策者,品牌系统本身保持克制、可信、现代;不走二次元 / 土萌路线。
- **能力诚实。** 性格里"靠谱"是底线——对外话术只讲已兑现的能力,愿景型卖点(如结构化记忆)明确标"在路上",不当既成事实硬吹(见第 6 节)。

## 5. 视觉与命名一致性方向

> 配色 / 字体 / logo 最终由设计师在实做时锁定,以下为方向,确保与"干练数字同事"的气质和 `Otto` 字标一致。

### 5.1 字标(Wordmark)

- 正式写法:**Otto**(首字母大写,其余小写)。CLI 产品:**Otto Code**。
- 西文几何无衬线为主,收尾干净利落,呼应"干练、办完就走"的性格;`-ly` 收尾可做轻定制以强化记忆点。
- 中英混排时:中文用一款现代、清晰的可商用无衬线(思源黑体 / HarmonyOS Sans / 阿里巴巴普惠体一类,**务必确认商用授权**);最多两个字族(中 + 西),`font-display: swap`,只预加载关键字重。

### 5.2 配色方向

- **定调:稳而不冷。** 主色用一个有信任感、不刺眼的色(偏沉静的蓝 / 青,或一个克制的品牌色),中性深灰做文字与骨架保证 B 端可信度,一组功能色覆盖状态(成功 / 警示 / 错误)。
- **纪律:** 用 CSS 自定义属性集中定义 token(`--color-brand` / `--color-text` / `--color-surface` …),不在组件里散落硬编码色值;暗色模式不默认开,按产品实际需要再定。

### 5.3 一致性收口

名字(Otto = done)、性格(干练数字同事)、Slogan(Consider it Otto)**同一血脉**,互相强化。凡对外露出,尽量让"Otto 字标 + 一句 Slogan"成对出现,降低记忆成本。

## 6. 命名与品牌的诚实边界(必须尊重,不许吹)

品牌话术必须与产品真实能力对齐。以下来自产品事实的诚实标注,**直接约束 Slogan 与对外宣传**:

1. **"懂你 / 记得你"是方向,不是现成事实。** 结构化记忆 / 按会话隔离("懂你岗位"护城河,P0 卖点)是**还没建的大特性**;当前记忆能力有限。
   - **约束:** "它记得你是谁"这类句子可作**愿景与方向**投放,**不可在能力兑现前当既成事实硬吹**;demo 与销售话术须与当期真实能力一致。
2. **产品形态是"本机 CLI 后端 + 飞书",不是云端多租户 SaaS。**
   - **约束:** 不把"云端 SaaS / 多租户"当卖点写进物料;讲清楚它跑在用户自己的电脑上(数据可不出域,这本身是合规卖点)。
3. **企业级能力(审计日志 / 速率限制 / RBAC)是路线图,不是已交付。**
   - **约束:** 这些只在"路线图 / 规划"语境下提及,不冒充已上线。
4. **Otto Desk / Work / Studio 是预留命名位,无对应产品。**
   - **约束:** 只在"产品家族规划"语境下提及,不当已发布产品宣传。
5. **与猎豹 / OrionStar 无关联;底座 Apache-2.0 合规保留。**
   - **约束:** 对外品牌 / 界面 / 文档全自有;源码 Apache 版权头按合规保留(用户不可见),分发时保留原作者归属与修改声明。

## 8. 名字作为工程配置(纪律)

为保留低成本改名的退路(商标 / 域名复检若爆雷需换名),工程与文档上把品牌名当**配置项**处理,不在代码 / prompt / 文案里散落硬编码字面量。

- 设单一品牌配置源(`brand.config` / 环境变量 / i18n 资源):
  - `brand.name` = `Otto`
  - `brand.product.cli` = `Otto Code`
  - `brand.slogan.primary.en` = `Consider it Otto.`
  - `brand.slogan.primary.zh` = `交给 Otto,就当办好了。`
  - `brand.agent.selfName` = `Otto`(注入 agent system prompt 自我介绍)
  - `brand.domain.primary` = `otto.com`
  - `brand.domain.ai` = `otto.ai`
- **代码、prompt、UI 文案、文档**一律引用配置键;agent 的自我介绍("我是你的数字同事 ___")从 `brand.agent.selfName` 取值。
- **切换成本预期:** 文案 / prompt 自称 / UI 字符串可一行切换;logo / 字标是设计件需替换;商标申请、域名、渠道 handle、ICP 备案改名 = 重走流程(这正是第 7 节必须先跑完的原因)。
