# 产品需求文档 · Otto

> 版本 PRD v2.0 ｜2026-06 ｜形态：**本机 CLI 后端 + 飞书**
> 一句话定位：**让每个员工，在飞书里拥有一个住在公司电脑上、懂他、替他干活的 AI 数字同事。**
>
> 本文是给团队和投资人看的产品需求文档。功能取舍锚定开源底座 **easycode**（Apache-2.0，源自 Google Gemini CLI）的真实源码实勘与已完成的工程验证。凡"承诺多过现实"的地方一律诚实标注，不吹。
>
> **与 v1.0 的根本差异**：本产品**不是云端多租户 SaaS**，而是**跑在用户自己电脑上的本机 CLI 后端**（部署形态与 easycode 一致），通过飞书与员工交互。本版据此重写定位、护城河、商业化与风险。

---

## 0. 文档导读（30 秒）

- **我们是什么**：基于开源 easycode 二次开发的**独立产品 Otto**。它是一个**跑在企业自己电脑/服务器上的本机 CLI 后端**，员工在**飞书**里就能喊它干活——查日历、写文档、盯任务、整理表格。它跑国产模型（DeepSeek/GLM）或复用本机 Codex 凭证，成本极低、数据可不出域。
- **我们不是什么**：① 不是云端多租户 SaaS（不卖"在我们服务器上开个账号"）；② 与猎豹移动 / OrionStar **无任何关联**（品牌、界面、文档全自有；源码深处的 Apache 版权头按合规义务保留、用户不可见）；③ 不是又一个"企业搭一个平台、全员共用一个 Bot"的低代码平台。
- **怎么赢**：在飞书官方 **Aily** 的"平台 + 让企业自己搭"模式之外，提供"**装上即用、开箱即懂业务**"的成品数字同事。**开箱即用 vs 平台搭建**，就是我们和 Aily 的分界线。
- **产品家族**：**Otto**（品牌总称）｜**Otto Code**（CLI，对标 Easy Code，本机 agent 后端，是当前一切的载体）｜**Otto Desk / Otto Work / Otto Studio**（家族其余成员，规划态，本文不为其编造未建成的能力）。
- **当前状态**：核心后端（Codex 双鉴权、多模型、全量 rebrand、安全止血、记忆并发安全、token 健壮性、会话回收）**已构建并实测通过**；护城河级大特性（结构化记忆 / 审计日志 / RBAC）**诚实标注为下一步、尚未建成**。

## 1. 定位与电梯陈述

### 1.1 一句话定位
> **一个住在公司电脑上、长在飞书里的 AI 数字同事——装上即用，懂业务，替员工干活。**

### 1.2 电梯陈述（30 秒版）
> 今天企业用 AI，要么是员工自己开个通用聊天框（不懂业务、不能动手），要么是 IT 在飞书 Aily 这类平台上"搭"一个 Bot（是个低代码工程项目，全员共用、产物归机器人）。**Otto 走第三条路**：它是一个**装在公司自己电脑上的 CLI 后端**（部署像装一个本地工具，不上传任何代码到我们的云），员工在**飞书**里直接喊它办事——它继承了一套已打磨成熟的飞书集成（18+ 业务域：日历、文档、表格、邮件、云盘、任务、OKR、知识库全打通），能真动手干活；它跑 **DeepSeek/GLM 等国产模型**或复用本机 Codex 凭证，成本极低、数据可留在企业内网。对标 Aily 是"给你一套工具去搭机器人"，**Otto 是直接把搭好的数字同事交到你手里**。

### 1.3 为什么是现在（时间窗口）
- **工程纵深现成**：飞书深度集成（WS 消息网关、扫码建应用、18+ 域 API 封装、CardKit 流式卡片、多群隔离会话）已由开源底座提供并经我们二次硬化，省去几个月地基。
- **成本拐点**：国产模型把单座位月成本压到极低，"给每个员工配一个"在经济上第一次成立；本机部署进一步把模型成本完全交给客户自带的 key。
- **结构性缝隙**：Aily 是"平台型"产品，天职是"通用 + 可治理 + 让企业自己搭"，这恰恰决定它在"开箱即用、本机部署、数据不出域"上有**结构性软肋**——不是没想到，是商业模式让它不会优先做。这就是窗口。

## 2. 目标用户与场景

### 2.1 三类角色

| 角色 | 是谁 | 核心诉求 | 我们给的价值 |
|---|---|---|---|
| **员工（主用户）** | 市场/运营/行政/HR/销售等一线非技术岗 | 少干重复劳动、别学新工具 | 在飞书里喊一声就办、它懂业务、不用学 |
| **部门负责人 / 老板（买单人）** | 痛感最强部门的 leader、中小企业主 | 团队提效、成本可控、别搞成大项目 | 一台电脑装上即用、整部门快速铺开、成本透明 |
| **IT / 管理员（守门人）** | 企业 IT、信息安全 | 可控、合规、数据别出事故 | **本机部署、数据不出内网**、可接私有模型、（下一步）审计留痕 + RBAC |

> **谁不是我们的用户**：① 钉钉/企微生态客户（深耕飞书 = 放弃跨平台，直接放弃不跟进）；② 工程师部门（自己写脚本、付费意愿低、爱挑刺）——冷启动不从工程部切。

### 2.2 核心场景（员工视角）
1. **找时间订会**："帮我找下周和张三都有空的 1 小时，订个会议室。"
2. **会议闭环**："把刚聊的纪要写成飞书文档发到群里。"
3. **任务跟进**："我这周还有哪些任务没交？到点提醒我。"
4. **文档表格代笔**："把这周的运营数据整理成一张表，发到周报群。"
5. **邮件分诊**（路线图）："今天邮件有啥要紧的，帮我拟个回复草稿。"

### 2.3 痛点与现状对比

| 现状 | 痛点 | Otto |
|---|---|---|
| 员工用通用 ChatBot | 从零开始、不懂业务、不能动手 | 懂业务、直接操作飞书、一句话跨模块编排 |
| 企业上 Aily 搭 Bot | 是个 IT 工程项目、全员共享、产物归机器人 | 装上即用、无需搭建、产物归员工本人身份 |
| 数据上第三方云 | IT 担心数据出域、合规过不了 | **本机部署、数据留在企业内网**、模型可自带 |

## 3. 护城河（对标飞书 Aily：开箱即用 vs 平台搭建）

### 3.1 战场定性：成品数字同事 vs 工具平台的代差错位

| 维度 | 飞书 Aily | 钉钉 AI 助理 | **Otto** |
|---|---|---|---|
| 本质 | 企业级 Agent **搭建平台**（低代码） | 平台内置官方助理 | **成品数字同事**：装上即用 |
| 谁来落地 | 企业 IT / 业务管理员搭建 | 平台 + 管理员 | **装一次后端、员工直接在飞书用** |
| 部署形态 | 字节云端平台 | 阿里云端平台 | **本机 CLI 后端（企业自己电脑/服务器）** |
| 数据归属 | 进字节生态云 | 进阿里生态云 | **可完全留在企业内网** |
| 操作身份 | 产物归机器人（应用身份） | 归机器人 | 走员工本人身份（user_access_token），产物归本人 |
| 模型主权 | 锁飞书/字节生态 | 锁钉钉/阿里生态 | **DeepSeek/GLM/Codex 可换可自带，本机部署可断网** |

**核心判断**：Aily / 钉钉是"平台"，平台天职是"通用 + 可治理 + 让你自己搭"，这恰恰决定它在"开箱即用、本机部署、数据不出域"上有**结构性软肋**——不是没想到，是商业模式让它不会优先做。**这就是缝。** 我们不在平台层正面打，只打它结构上做不到的三处。

### 3.2 护城河清单（按可防守强度排序，诚实标注成色）

> 护城河 ≠ "我们有个功能"，而是"对手即使看见也学不动 / 不愿学"。

**① 开箱即用 vs 平台搭建（强，最核心的定位差）**
Aily 把"企业级 Agent 落地"留成一个**需要 IT 搭建的低代码工程项目**；我们把它压成"**装一个本机后端、员工直接在飞书用**"。继承的飞书集成已覆盖 **18+ 业务域**，员工开口即办，不需要任何人去"搭工作流"。
- Aily 为什么学不动：不是技术难度，是**商业模式冲突**——Aily 的钱和治理逻辑建立在"卖平台、让企业自己搭"，做"装上即用的成品"等于自拆平台打法。

**② 本机部署 + 数据不出域（强，打数据敏感客户的杀手锏）**
Otto 是**跑在企业自己电脑/服务器上的 CLI 后端**（形态与 easycode 一致），不把代码、文档、对话上传到任何第三方云。配合"自带模型 key / 接本地模型"，可做到**数据完全不出客户网**。
- 这是云端 SaaS 平台 Aily **给不了**的客户——金融、政企、制造、信创清单内的企业，本机部署是硬门槛。
- **已就绪**：底座原生支持"自定义模型（无需登录）"模式，几乎零改造即可接 DeepSeek/GLM/自建模型。

**③ 个人长期记忆 + 业务画像（潜力最强，目前最虚，必须砸资源做实）**
Otto 跨会话记住"这个人是谁、负责什么、偏好、历史决策、常打交道的人和文档"，越用越懂。这是真正能锁客户多年的**数据飞轮**——用得越久迁移成本越高。
- 🚧 **现状缺口（不粉饰）**：当前记忆只是把事实**追加进项目根的 `DEEPV.md` 文本文件**（`memoryTool.ts`）。我们**已经做完的是"并发写安全"**——记忆并发写已串行化，实测 **20/20 并发零丢失**（解决了审计中的竞态丢失问题）。但**结构化、按会话隔离、检索、业务画像、从飞书行为自动学习仍未建成**。**这条护城河现在深度仍浅，"天生懂你"目前是承诺多过现实。这是 R&D 第一优先级（见路线图）。**

**④ 飞书全域深度集成 + 工程硬化的"既成事实"（中强，工程纵深）**
继承的 `lark-cli` 已覆盖 **18+ 飞书业务域**，且有 WS 长连接网关、OAuth 动态接管、消息去重/重连/限流、多群隔离会话等大量**真实踩坑后的工程细节**；我们在此之上**已完成系统性安全与稳定性硬化**（详见 §4.1）。一个从零做飞书 agent 的创业公司，光把这 18 个域接稳、再补齐这些安全洞，就够喝一壶。
- **取舍**：深耕飞书 = 放弃钉钉/企微。飞书生态外客户直接放弃，不浪费销售资源。

**⑤ 模型中立 + 双鉴权（中强，成本与合规弹性）**
可换 DeepSeek/GLM/Codex，可自带 key，可接本地模型。**已完成并实测**：Codex 双鉴权（OAuth + API Key，实测 HTTP 200 + 文本流）、多模型配置（`custom-models.json` 可配多条 Codex/DeepSeek/OpenAI，`/model` 一键切换）。**明确不碰 Claude OAuth**（订阅 OAuth 调 API 会被封号，模型层只走合规 API Key / Codex）。

> **诚实定级**：开源底座本身**不是护城河**（对手也能 fork 同一上游）。它的价值是**早期速度与成本结构**，不是长期壁垒。真正的壁垒是叠加在底座上的私有部分——开箱即用的产品化（①）、本机部署的合规能力（②）、记忆飞轮（③）。对客户别讲"我们开源"，客户不关心；当内部研发杠杆用。

## 5. MVP 范围

### 5.1 MVP 一句话
> 在企业一台电脑上装好 Otto 后端，员工在飞书里就能让它查议程 / 订会 / 写文档 / 整表 / 盯任务，跑在国产模型或本机 Codex 上，记忆并发安全、操作经过安全硬化。**砍掉一切"搭建 / 协作 / 编排平台"，把"装上即用 + 懂业务 + 几件高频活"做到惊艳就赢。**

### 5.2 MVP 必做（多数已完成）

| # | 必做 | 状态 |
|---|---|---|
| M1 | 飞书接入：单聊 / 群 @ / 流式卡片回复 | ✅ 现成（已硬化） |
| M2 | 多模型可配可切（Codex / DeepSeek / OpenAI） | ✅ 完成（C2） |
| M3 | 安全底盘：RCE / 密钥泄露 / 注入全封堵 | ✅ 完成（C4） |
| M4 | 记忆并发安全（结构化升级放路线图） | ✅ 并发安全完成（C5）；结构化待建 |
| M5 | 3 个高频技能扎实：① 日历 ② 文档代笔 ③ 任务 | ✅ lark-cli 全有，做品牌化打磨 |
| M6 | 高危操作二次确认卡片 | 🔶 卡片回调现成，接线 |
| M7 | demo 打磨：话术、卡片视觉、黄金路径录屏 | 🆕 |

### 5.3 明确不做（MVP 内一律砍）
向量 / 语义记忆检索 · 数字同事互相转派 · 低代码搭建工作流 · 邮件/云盘/OKR/知识库全量技能 · 多模型自动路由 · Web 管理后台 · 企业审计日志 / RBAC（放路线图）· 钉钉/企微适配。

### 5.4 Agent 人设：它不是"AI 助手"，是"你工位隔壁的新同事"
**语气宪法 5 条（写进 system prompt）**：① 先结论后展开，手机第一屏必须有用；② 像同事不像客服（不用"非常抱歉给您带来不便"）；③ 不懂只问最关键一个，绝不杜撰事实；④ 对外 / 不可逆动作永远先拟稿等确认；⑤ 说人话、排版给手机（不输出超宽表格）。

## 6. 路线图

> 结构：**已完成的硬化（底盘）→ 下一步护城河大特性 → 更远期。** 大特性诚实标注为"尚未建成"。

### 已完成（底盘硬化，详见 §4.1）
Codex 双鉴权 · 多模型配置 · 全量 rebrand · 安全止血（多类 RCE/注入/密钥泄露封堵） · 记忆并发写串行化 · token 链路健壮性 · 会话 idle 回收。

### 下一步护城河（P0，尚未建成，决定能不能赢）
- **结构化记忆 / 按会话隔离**——把记忆从"追加文本"升级为结构化、可按员工/会话隔离、可注入岗位画像的存储。这是"懂你岗位"护城河的核心，**P0 卖点**。当前深度仍浅，必须最先砸资源做实。
- **企业审计日志**——谁让数字同事做了什么、操作了哪些飞书资源，全程留痕。**合规刚需**，是说服 IT / 拿政企单的门槛。
- **RBAC**——按角色控制谁能用哪些技能、操作哪些资源。企业级权限边界。
- **速率限制**——防滥用、控成本、保稳定。
- **Codex token 自动刷新实跑验证**——代码已就绪，到期或人工触发后补验证闭环。

### 更远期
- 记忆升级到向量检索 + 企业知识库 RAG
- 技能铺开：邮件分诊 / 云盘 / OKR / 知识库问答 / 妙记纪要
- 主动性：定时早报、到点提醒
- 私有化部署包（全栈国产模型 + 内网，主攻政企/金融/制造/信创）

> **架构红线（支撑路线图不返工）**：业务代码**绝不直接 import 具体存储/审计/计费 SDK**——全走 interface，本机部署注入本地实现，未来如需托管再注入对应实现。这是"本机部署"这条命门第一天就不被锁死的前提。审计与 RBAC 设计应复用底座现有的 Turn 钩子（BeforeModel/AfterModel）与会话上下文，而非另起一套框架。

## 7. 商业化（按席位 + 国产模型成本）

### 7.1 成本结构（本机部署：模型成本天然可转移给客户）
- **本机部署形态**下，模型 API 由**客户自带 key 或接本地模型**，**模型成本可完全转移给客户**——我们卖的是产品授权 + 实施 + 升级，不背模型账单。
- 若我们代为提供国产模型聚合，则吃**国产模型的低成本红利**：DeepSeek/GLM 单座位月模型成本极低（重 context 负载下，命中 prompt cache 后输入价是未命中的数十分之一，缓存命中率是毛利命门）。

> ⚠ 具体单价随模型厂商调整，合同口径以签约时官方最新价为准，**不在 PRD 锁死过期价格**。建模假设需 Pilot 实测校准。

### 7.2 定价档（per-seat，核心卡位 = 用固定价打 Aily 的"平台 + token 计费不可预测"焦虑）

| 档位 | 形态 | 对象 | 逻辑 |
|---|---|---|---|
| **Free Pilot** | 本机部署，限 1 部门小范围、限期 | 冷启动钩子 | 让"装上即用"被亲眼看到 |
| **Team 标准版** | 按席位 / 月（年付折扣） | 中小企业、单部门铺开 | 低于一个普通飞书席位，心理账户是"加个 AI 同事" |
| **Business 进阶版** | 按席位 / 月 | 跨部门、要审计 / RBAC | 兑现下一步合规特性后开放 |
| **Enterprise 私有化** | License + 实施费 + 运维 | 政企 / 金融 / 制造 / 信创 | 客户自带 key / 本地模型，模型成本转移给客户 |

> **定价原则**：**坚决不按 token 计费给客户**——"给小王配个 AI 同事 X 元/月"比"你这月用了 230 万 token"好卖一百倍。固定 per-seat 价正好打 Aily 平台计费的不可预测焦虑。

### 7.3 冷启动：Land in one team, expand by envy
切"痛感最强 + 重复劳动最多"的部门（HR / 运营 / 行政助理，**别从工程部切**）→ 一台电脑装上 Otto 后端、给整部门开通 → Otto 在飞书群里发周报、@催办、丢纪要 → 别的部门看到"他们有个 AI 同事在群里干活"会主动来问（飞书 IM 形态天然适合病毒扩散）→ 部门负责人转化为内部冠军，向上要预算铺全公司。

**话术主轴**："Aily 是给你一套工具去搭机器人，Otto 是直接把搭好的数字同事交到你手里。" 不抢"企业级 Agent 平台"这个被 Aily 占住的词，占"开箱即用的数字同事"这个空位。

## 8. 风险与红线

### 8.1 产品 / 技术红线

| 风险 | 应对 |
|---|---|
| **记忆护城河现在仍浅**（"懂你岗位"目前承诺多于现实） | 已完成并发安全；结构化 / 按会话隔离列为 R&D 第一优先（路线图 P0），不靠营销话术兜底。 |
| **把 `delegate_to_agent` 当 agent 协作卖点 → demo 穿帮** | MVP 绝口不提 agent 协作。 |
| **Codex token 自动刷新未实跑** | 到期或人工触发刷新路径补验证；刷新逻辑已隔离在单方法，出错可定点修。 |
| **审计 / RBAC / 速率限制尚未建成** | 在对外材料中标注为"路线图"，不承诺为现有能力；架构上预留 interface 不锁死。 |

### 8.2 必输场景（看见就避开，别送人头）

| 场景 | 应对 |
|---|---|
| 钉钉 / 企微生态客户 | 直接放弃，销售不跟进。 |
| 企业要"统一治理、IT 集中管控、自己搭工作流"（Aily 主场） | 不正面投标；必须时绑本机私有部署 + 数据不出域打。 |
| 复杂跨系统流程编排（ERP/CRM 深度打通） | 明确边界，不承诺，转介或集成而非自建。 |
| 纯比"模型多强"的 POC | 拽回"开箱即用 + 业务画像 + 数据不出域"主场再打。 |

### 8.3 模型合规红线
- **模型层只走合规 API Key / Codex 凭证，绝不碰 Claude 订阅 OAuth（会被封号）。** 底座"自定义模型（无需登录）"模式天然满足；Codex 双鉴权已实测，复用本机 `~/.codex/auth.json`，**不接任何 Anthropic OAuth 刷新逻辑**。
- 数据：本机部署优先，数据可完全不出客户网；Embedding 用国产合规模型（BGE/GLM），不出境。

### 8.4 Apache-2.0 开源归属红线（法务必读）
- 底座 LICENSE 为 **Apache-2.0**（源自 Google Gemini CLI）。
- **硬性义务**：二次开发分发时**必须保留 LICENSE 与 NOTICE、保留版权与归属声明**，并在显著处声明对原作品的修改。**品牌另起没问题，但不能抹掉原作者署名**——否则违反许可证，既是法律风险也是商誉风险。源码深处的 Apache 版权头按合规义务保留、用户不可见。
- **可做**：闭源我们叠加的私有部分（结构化记忆、审计、RBAC、产品化）——Apache-2.0 允许在衍生作品中加专有代码，只要原 Apache 部分的义务履行。
- **与猎豹 / OrionStar 无任何关联**——品牌、界面、文档全部自有。

### 8.5 飞书私有协议单点风险
- 部分"扫码自动建应用"能力依赖飞书**未公开的私有协议**（底座源码注释白纸黑字写"飞书可能任意更改 / 下线"）。**这是便利，也是单点故障。**
- **应对**：必须并行保留"手动 app_id / secret 接入"的优雅降级路径，监控该端点健康度；命脉不押在私有协议单点上。
