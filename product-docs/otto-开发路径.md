## 一、战略判断(先看这段)

**一句话**:Otto 的地基是真的、能跑;真正拖后腿的不是"功能少",而是**三件事**——① 最招牌的愿景(A-to-A / 多渠道 / 飞书穿梭)在代码层是**会谎报成功的空壳**;② 平行系统在膨胀(3 套记忆 + 3 个前端,互不打通);③ 开箱状态下半数能力因缺依赖当场哑火。

**因此开发路径的总原则不是"往上堆功能",而是**:
1. **先收敛,再新增**——定主干、并/砍平行线,把"假成功壳"止血,否则任何新功能都建在流沙上。
2. **押真护城河,别演假愿景**——Otto 真正防守得住的是「真把办公任务干完 + 干活即沉淀知识 + 数据留本机 + 老板看得到 ROI」,**不是 A-to-A**(那是 12 个月的远景,现在是壳)。把力气投在护城河,愿景层"做一个真闭环胜过五条假链"。
3. **每阶段交一个能在别人机器上跑通、能录屏的 demo**,不是 PPT。

## 二、三个必须先拍板的决策(阻塞后续,建议你先定)

这三处不定,团队会继续各开各的平行线。给出我的建议 + 理由,你改一个字就行。

### 决策 1 · 主干分支
**建议**:`internal` 为唯一主干;`otto-enterprise` 是团队工作区,**择优 cherry-pick 进 internal,facade/死代码/硬编码他机路径一律不进**。建立合并门禁(见第五节)。
**理由**:两分支已出现"同一功能两套假壳"(A2A)、"提交 message 与 diff 不符"。不设门禁,假成功壳会顺着 merge 漏进主干。

### 决策 2 · 记忆系统主干(现在有 3 套)
现状:①企业 SQLite(`~/.otto-enterprise/data.db`)②memory-manager markdown(`~/.otto/memory`)③新 org/project JSON(`.otto/org/`)。三套零引用。
**建议**:**分两条轴,各一个主干,别再混**——
- **组织/HR 轴**(员工/任务/知识/画像/审计/看板)统一到**企业 SQLite**;把 memory-manager 的算法(discoverPatterns/脱敏)搬进 SQLite 侧;markdown 降级为"离线个人缓存"或退役。
- **开发者/项目轴**(项目决策/代码库记忆)保留新 org memory,定位清楚它服务的是"写代码时的项目记忆",**不混进企业 HR**。
- core 提供一个 `MemoryGateway` 抽象,上层工具只认 gateway,底层可切 SQLite/文件。
**理由**:PostExecHook 现在把"自动 learn"写进 markdown、企业看板读的是 SQLite,两边不通 → 自动学的东西进不了企业知识库,这是"知识沉淀"卖点的硬伤。

### 决策 3 · 前端主干(现在有 3 个)
现状:cli(内核入口)/ desktop-renderer(最完整,有测试)/ 新 packages/web(脚手架+桩)。
**建议**:**desktop-renderer 为 GUI 主干**;把它的 React 组件抽成共享包,web 若要留**必须复用同一套组件 + 走 server 的 WS/HTTP API**(删掉 spawn CLI、硬编码 `/Users/king/...` 路径、命令注入),否则**砍掉 packages/web**。cli 保留。
**理由**:web 现在是从零 create-next-app + 壳套 CLI,不复用已有前端、跑不到别的机器,是三者里最粗的一个,继续留只会分裂维护。

## 三、开发路径:四个阶段

### 阶段 0 · 定主干 + 止血(本周,先决条件)

**目标**:消除"假报成功"和平行膨胀,给后续一个干净地基。不加新功能。

| 事项 | 怎么做 | 验收 |
|---|---|---|
| 落实决策 1/2/3 | Felix 拍板 → 团队执行 | 三个决策写进 CLAUDE.md/AGENTS.md |
| `multi_channel` 止血 | 补真企微/钉钉 API **或** 从工具注册摘除/改 fail-loud(未实现就明确报"未接通",禁止 status 硬编码"全部已连接") | 模型再调它不会谎报送达 |
| 两套 A2A 死代码 | 移到 `experimental/` 或删,不进主干构建;protocol.ts 的类型可留作 V2 设计 | 主干构建里无 971 行死代码 |
| 飞书一键开关 | 补 main 进程缺失的 `ipcMain.handle('otto:feishu-*')` 接到已存在的 feishuDaemon,**或**先隐藏按钮 | 点了真能启停,或不误导 |
| web 安全 | 立即去掉硬编码他机路径 + 堵命令注入(不拼 shell,用参数化) | 无注入、无他机路径 |
| 吉祥物面板 | 标注为"占位",或接真数据,或从默认布局撤下 | 不以假数据示人 |

### 阶段 1 · 地基夯实:让现有能力经得起真用/演示(2–3 周)

**目标**:现有能力开箱可用、演示不露馅。这是"去 Demo 感"。

1. **依赖体检 `doctor`(最高优先)** — 解决"开箱半数能力哑火"。
   - 实现:core 侧 `DoctorService` 探测 ~10 个二进制(pandoc/libreoffice/typst/marp/duckdb/gnuplot/cliclick/ffmpeg/whisper/playwright/gs)的存在+版本+权限;暴露为 `doctor` 工具 + CLI 命令 + 桌面"环境体检"卡;缺失时按平台给 `brew/winget/npm` 安装命令。各 dep-gated 工具执行前先过 doctor。
   - 验收:换一台没装齐的机器,`otto doctor` 一次性列清缺什么、怎么装;工具不再"跑到一半才崩"。
2. **子功能补真**(去露馅):真饼图(gnuplot 极坐标/SVG)、Typst 封面模板、合并保真(PDF 走 pdfunite/gs 而非转 md)、md2typst 换 `pandoc -t typst`、多维透视表、voice 静音检测自动停录。
   - 验收:每项加"对外部引擎真实输出的断言"测试(不止测参数)。
3. **浏览器自动化重写**:playwright 进 `optionalDependencies` + postinstall 引导 `npx playwright install`;改**常驻会话**(持 page 对象跨 action / CDP 连已开浏览器);接通 firefox/webkit 分支。
   - 验收:`navigate→fill→click` 三步在同一页面真连贯生效。
4. **PostExecHook 补真**:改成写**企业 SQLite knowledge 表**(而非本地 markdown)+ 加一层真"结果归纳"(小模型/规则从 result 提炼要点,而非入参前 200 字)。
   - 验收:自动学的知识能在企业看板/recall 里检索到。

### 阶段 2 · 企业治理层:让 "Enterprise" 名副其实(3–4 周)

**目标**:把"个人聊天工具"补成真企业产品。这是差异化护城河的一半(另一半是知识沉淀)。

- **用量&成本看板**(数据已采集,只差聚合 UI)+ **看板补图表**(效率趋势折线/瓶颈/按员工对比)+ **修 ROI 灌水**(去掉 685× 误导、倍率可按任务配置、显式展示假设、修 3×/2× 文案打架)+ **员工可钻取**。
- **审计视图**(只读时间线,分页/时间筛选/导出)。
- **RBAC 分级**(员工/经理/管理员 token;补 `/task` 上报鉴权,防任何人灌数据污染报表)。
- **集中脱敏管道** `redact()`:手机/邮箱/身份证/银行卡/中文姓名(NER),对**所有**对外流出(export/知识合并/同步)统一过滤。
- **export 去 1000 上限 + SQLite 文件级备份/恢复**。
- **企业端测试**(鉴权绕过/邀请码复用过期/报表聚合/脱敏有效性)。
- **桌面端集成企业 server**:管理员在桌面 app 里一键起 server + 开看板,不再走命令行。
- **真 offboard 方法论提取**:替换现在的计数模板句,从 task_logs 聚类高频步骤+耗时基准生成真 SOP。

### 阶段 3 · 愿景第一版:做一个真闭环,而不是假壳(4–6 周)

**目标**:把被产品文档当核心卖的 A2A/穿梭,从"假成功壳"换成"一个真能演示的最小闭环"。宁可一条真链,不要五条假链。

1. **飞书穿梭真闭环(先做这个)**:挑 1 条高频链路真做通,例如
   `从飞书表格读数据 → 本地 DuckDB 分析 → 生成报告 → 上传回飞书云盘 → IM 通知`。
   - 实现:基于已有真实的 feishu IM 链路 + 把 Sheets/Drive 从"转调外部 lark-cli"升级为 server 侧原生封装。这就是把 feishu-shuttle 的 `placeholder` 换成真调用。
   - 验收:一句话触发,飞书内外真的都动了(有真副作用,能录屏)。
2. **A2A 最小切**:复用**飞书群当信道** + 现有 **SubAgent/delegate 当执行体**,新增"来自另一个 Otto 的任务卡"消息类型解析 → 落任务 → 跑 → 回帖。**先做人在环**(每步可审批),再逐步自动。不做跨机跨网络重基建。
   - 验收:两个 Otto 实例,一个发任务卡、另一个真接真跑真回,人只说第一句、看最后结果。
3. **多渠道**:若要留 `multi_channel`,补真的企微/钉钉 gettoken + 消息 API(真副作用);否则保持 fail-loud。

## 四、开发方式(横切工程纪律 —— 回答"怎么开发")

针对这轮暴露的"假成功壳"问题,方式层必须立规矩:

1. **反假成功壳 = Definition of Done**:任何工具/功能"完成"的标准 = **有一次真实端到端运行的证据**(截图/日志/真副作用)。禁止"返回 success 但零副作用"。做不到真的就 **fail-loud**(明确报"未实现/依赖缺失"),**绝不谎报成功**。
2. **收敛优先于新增**:每阶段先并/砍平行系统,再加新功能。**禁止再开第 4 套记忆 / 第 4 个前端**。
3. **合并门禁**(cherry-pick enterprise→internal):**看 diff 不看 commit message**;facade / 死代码 / 硬编码他机路径 / 命令注入一律打回。
4. **依赖门禁**:`doctor` 进 CI + 启动自检。
5. **每阶段一个可演示切片**:结束都要有"能在别人机器跑通、能录屏"的 demo。
6. **测试红线**:对外卖点(鉴权/脱敏/报表/知识检索)必须有测试;工具测试断言真实引擎输出,不只测参数。

## 五、实现方案(横切架构 —— 回答"用什么方案")

- **记忆统一**:企业 SQLite = 组织级事实源;memory-manager 算法搬进 SQLite;org/project memory 独立轴;core 出 `MemoryGateway` 抽象,工具只认 gateway。
- **前端统一**:desktop-renderer 组件抽 `packages/ui` 共享包;web(若留)复用组件 + 走 server API;一份组件两处壳(Electron/Next)。
- **能力工具**:全部 dep-gated 工具统一走 `DoctorService` 前置 + 统一临时目录管理 + "引擎缺失→fail-loud+安装引导"。
- **A2A/穿梭**:不自建新协议栈;复用飞书作信道 + 现有 SubAgent/delegate 作执行体;消息层加"Otto 任务卡"类型;先人在环再自动。
- **飞书业务域**:高频域(Calendar/Sheets/Drive)从"转调 lark-cli"升级为 server 侧原生封装,接进桌面/飞书会话。
