一句话:Otto 是住在飞书里、跑在你电脑上、能替你干活还能写代码的 AI 同事。下面用图,一页讲一个点。

① 一个回路② 数据在哪③ 怎么用④ 内部怎么走⑤ 现在到哪了
01 — 心智模型
先记这一个回路

整件事,就一个闭环

后面每一页,都是这个回路里某一段的放大。

02 — 它不是云网站
区别只有一个:数据在谁的机器上

普通云 SaaS vs Otto

所以把它想成 "一台你自己的电脑,挂了个飞书机器人账号" —— 不是网站,不需要服务器,内网就能跑。

03 — 怎么用
用起来就一句话

@ 它,
说人话

不点菜单、不找入口。你怎么跟同事交代,就怎么跟它说。它一边干一边报进度,干完把结果发回聊天。

私聊 / 群都行支持语音 / 文件

04 — 它能干两类事
两条线,一套机制

办公 与 写代码,同一双手

对它来说,"调飞书 API" 和 "改你电脑上的代码" 是同一种动作 —— 这就是它能两手抓的原因。

05 — 内部怎么走
你刚那句话,内部这么流动

一条消息的旅程

起点终点都在飞书;中间三段(网关→大脑→工具)就是它替你干活的地方。

06 — 四个角色
把它当一个"数字员工"

流程上的每一段,谁在管

💬飞书
入口

你发消息的地方,也是结果回来的地方

→
📡网关
前台 + 门禁

连飞书、收发消息、认出是谁、按白名单放行(凭证加密)

→
🧠大脑
员工本人

会写代码的 AI:理解、决定、多轮推理

→
🛠工具
手脚

一手 lark-cli 操作飞书,一手操作你电脑的代码

你之前看到的那堆文件名(gateway / agent / lark-cli / credentials),就是这四个位置。

07 — 多群会不会乱
一个常见疑问

很多群同时用,怎么不串台

群 A · 产品组
群 B · 研发组
私聊 · 你
→
各自
独立→
会话 A:产品组的上下文
会话 B:研发组的上下文 + 绑定的代码库
会话 C:你的私人上下文

每个聊天 / 群 = 一条独立会话,各记各的,互不干扰;还能把某个群锁定到某个项目。 ⚠️ 诚实说:极端高并发下的隔离还在加固(见下一页)。
