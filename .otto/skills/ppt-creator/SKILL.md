# PPT 视觉导演

把内容做成能在会议室真正讲清楚、缩略图也有节奏的演示。HTML 是视觉画布，不是把旧式 Python/PPT 模板换一种技术复刻；最终目标是审美、叙事和信息层级，不是“成功生成文件”。

## 硬约束

- 固定使用：HTML/CSS/SVG 排版 → Playwright 或本机 Chromium 浏览器渲染 → 逐页 PNG → Node.js + PptxGenJS 组装 PPTX。
- 禁止使用 Python、python-pptx、matplotlib、Pillow 或任何 Python 脚本完成布局、图表、截图、图片处理或 PPTX 写入。
- 不把 Markdown 直接丢给通用模板批量生成。每页必须经过有意识的视觉构图。
- 不上传普通 PPT，不依赖 Otto 私有服务或云端编辑器；只在用户明确要求在线协作时使用远程能力。
- 用户没有要求逐步确认且素材已足够时，直接完成；只对会实质改变方向的缺失信息提问。

## 先定一句话

在动手前明确：

- 核心结论：听众离场后必须记住的一句话。
- 受众与场合：谁看、在哪里讲、需要做什么决定。
- 时长与页数：默认每页承载 1–2 分钟讲述。
- 品牌与素材：Logo、品牌色、指定图片、数据来源和不能改动的内容。

信息足够就直接选择合理方向，不用把用户拖进漫长问卷。

## 先做故事板，再做页面

1. 把材料压缩成“背景 → 张力/问题 → 证据 → 洞察 → 方案 → 行动”的叙事弧。
2. 一页只表达一个可复述观点；标题必须是结论句，不使用“市场分析”“解决方案”这类空标题。
3. 为每页标注页面类型与视觉角色，主动安排节奏：
   - 封面：一句强标题 + 克制副标题 + 视觉锚点。
   - 章节页：大留白或沉浸式图片，负责换气。
   - 观点页：一个主张 + 一项证据，不堆清单。
   - 数据页：一个关键数字或一张主图表，结论先于图表。
   - 对比页：明确对照轴，突出差异而不是画两个相同盒子。
   - 流程/时间线：呈现方向、阶段和关系，不做装饰性箭头。
   - 案例/场景页：图片、引语或结果主导。
   - 收束页：回扣核心结论并给出下一步。
4. 连续三页不得使用同一种构图；整套至少包含 4 种不同页面类型。

## 选择并锁定视觉方向

根据主题只选择一个清晰方向，例如：编辑杂志、瑞士现代主义、电影感、精密科技、克制奢华、温暖人文或大胆几何。不要混搭成“什么都有”。

先在 CSS 变量中定义：

- 2 个基础色 + 1 个强调色，强调色只用于真正重要的信息。
- 1 套中文字体栈和 1 套数字/英文字体栈；优先本机可靠字体，等待字体加载完成再截图。
- 12 栏网格、统一安全边距和 8pt 间距节奏。
- 背景、文字、弱文字、分隔线和强调色，不在每页重新发明颜色。
- 圆角、阴影和描边只选必要的一种表面语言，不能全部叠加。

以 1920×1080 画布为基准：

- 四周安全边距建议 88–120px。
- 封面标题约 72–104px，页面标题约 46–64px，正文约 28–36px；非脚注文字不得小于 24px。
- 每页保留约 25%–40% 有意义的留白。
- 正文通常不超过 3 个短块；需要解释的细节放讲者备注，不塞进页面。

## 用视觉表达，不用盒子收纳

优先使用：

- 强字号对比、错位与非对称构图。
- 全幅或局部裁切的高质量图片。
- 大数字、引语、单一图表、路径、时间线和前后对照。
- SVG 绘制的数据图表与示意图，保持线条、字号和颜色一致。
- 有意义的对齐、留白、叠放和视线引导。

图片必须服务观点。优先使用用户素材；缺图时按权限使用 imagegen 或合规图片来源，并检查清晰度与裁切。不得用一排小图标假装视觉设计。

## HTML 页面规范

- 使用一个本地 HTML 文件承载全部页面，或使用共享样式的逐页 HTML；每页根节点固定为 `<section class="slide">`。
- 固定 `.slide { width: 1920px; height: 1080px; overflow: hidden; position: relative; }`，禁止依赖浏览器窗口自适应决定最终布局。
- 使用 CSS Grid/Flex 做主结构，使用绝对定位完成必要的艺术化叠放；不要用大量坐标硬拼文字。
- 图表优先输出内联 SVG；数据、标题和备注另存为结构化 JSON 或 Markdown，避免把事实散落在脚本里。
- 等待 `document.fonts.ready`、图片解码和 SVG 渲染完成后再截图。
- HTML 只负责画布渲染，不展示导航栏、按钮、滚动条或浏览器式交互控件。

## 浏览器渲染与 PPTX 组装

1. 用 Playwright 或本机 Chrome/Edge/Chromium 打开本地 HTML。
2. 以精确 1920×1080 视口逐页截图，输出按顺序命名的逐页 PNG，例如 `slide-01.png`。
3. 使用 Node.js 和 PptxGenJS 创建 `LAYOUT_WIDE` 演示文稿。
4. 每页把对应 PNG 以满版方式放到 `x=0, y=0, w=13.333, h=7.5`，不得拉伸变形或留白边。
5. 支持时用 `addNotes()` 写入讲者备注；备注不应烧进页面图片。
6. 写出 PPTX 后检查文件存在、大小合理、页数正确，并重新打开或渲染抽查。

如果环境缺少浏览器或 Node 依赖，先报告真实缺口并尝试范围内可用的 Node/浏览器方案；禁止悄悄改用 Python。

## 反模板审美禁区

- 不要把幻灯片做成网页后台、SaaS 落地页或数据看板。
- 禁止“白底 + 蓝色顶栏 + 四个等宽圆角框”的默认企业模板。
- 避免重复卡片阵列、满页 bullet、每页同一个标题栏和无意义页脚。
- 避免大面积紫色渐变、玻璃拟态、发光描边和装饰性 3D 图标，除非主题明确需要。
- 不用小字号塞内容，不把长段落缩小到“勉强放下”。
- 不为填空而加图片、图标、箭头或图表。
- 不让每页都同样满、同样空或同样对称；整套必须有张弛。

## 强制视觉验收

交付前完成两轮检查：

1. 缩略图总览：把所有页面以小尺寸同时查看，检查叙事节奏、色彩分布、页面类型变化和是否出现重复模板。
2. 逐页 100% 检查：确认无溢出、裁切、重叠、低清图片、错别字、孤行、过小文字、错误数据和对比度问题。

任何一页在缩略图里无法看出主次，或连续页面像复制粘贴，都必须返工。至少重点复查封面、最复杂的数据页和结尾页。

## 交付

- 交付可打开的 `.pptx`，并保留 HTML 源文件与逐页 PNG，方便复核和二次生成。
- 报告真实绝对路径、页数、画布尺寸和实际使用的渲染链路。
- 数字、引用和图片来源必须可追溯；不确定内容明确标注，不编造。
