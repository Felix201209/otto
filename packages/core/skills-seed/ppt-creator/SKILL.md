# PPT 创作

把零散内容变成一份有叙事、有节奏、可直接讲的演示。

## 开工先问清（缺一不可）
- 主题与核心结论（这份 PPT 想让听众记住的一句话）
- 受众（决策层 / 同事 / 客户 / 学生）与场合
- 时长 → 反推页数（约 1.5–2 分钟一页）
- 风格（商务简洁 / 数据驱动 / 视觉冲击）

## 叙事结构（默认骨架，可裁剪）
1. 封面：标题 + 一句副标题点明价值
2. 背景/问题：为什么此刻重要
3. 核心论点：一页一个观点，通常 3 段
4. 证据：数据、案例、对比，每个论点配 1 页支撑
5. 方案/行动：具体建议、下一步
6. 结尾：回到核心结论 + 行动号召

## 每页产出格式
- 标题：陈述观点，别用名词堆砌（"成本下降 30%" 优于 "成本情况"）
- 正文：3–5 个要点，每点一行，动词开头
- 讲者备注：这页要口头补充/强调什么
- 视觉建议：该配图表/示意图/大字/照片，给出具体建议

## 本地文件交付
- 用户确认大纲后，把逐页内容整理成 Markdown，每页之间使用独占一行的 `---` 分隔
- 调用 `generate_document`，参数固定为 `format="slides"`、`output_format="pptx"`，并写入用户指定或明确报告的本地绝对路径
- 固定渲染链路：每页本地 HTML → 本机 Chrome/Edge/Chromium 截图 PNG → Node 封装 PPTX；禁止改走 Python 脚本
- 兼容旧 `/ppt` 流程时可以调用 `ppt_generate`；它同样只在本机渲染
- 不把普通 PPT 生成路由到 Otto 私有服务，不要求云端 URL，不登录、不上传、不打开云端编辑页
- 只有用户明确要求“飞书幻灯片/在线协作”时，才使用对应的飞书远程能力

## 纪律
- 一页一个观点，不塞满
- 数字必须有来源或标注"示例"，不编造
- 先给整体大纲让用户确认，再逐页展开
